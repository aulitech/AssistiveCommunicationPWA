# Saying when something failed

> One of the decisions behind Peri, moved out of [AGENTS.md](../../AGENTS.md), which keeps the map of
> the source and the rules that hold everywhere. What is written here is why the code is the shape it is.

Every service call in this app is written so that failing changes as little as possible: sync fails into a line of text under a setting, a translation fails into the words as they were written, an ElevenLabs voice fails into the device's, a service worker that will not register leaves an app that still runs. That is the right behaviour, and it is exactly what makes these failures invisible — **a board that carries on working looks like a board with nothing wrong**, and the first question anybody debugging one has is what the service actually said.

`reportFailure(where, what)` in `core/report.ts` is the one shape they all take: `[Peri] sync/pull: Server said 500`. `where` names the thing that failed the way the source tree does, so the console can be filtered and the code grepped.

- **Never the words, and never the key.** What goes in is the operation and the failure Peri would already show a user — a status code, a refusal, "could not reach". A phrase belongs to the person who wrote it, and a console ends up in every screen-share and bug report from then on; a key in a console is a key in a screenshot. `tests/translate/client.test.ts` holds that line.
- **Only what is actually a fault.** A 409 from sync is somebody else writing first, which the next poll reconciles — no warning. A parser refusing a damaged backup, a `localStorage` read finding nothing, `Intl.DisplayNames` missing: all of those are defined paths with a defined answer, and warning about them would fill the console during normal use. A *write* that fails is different, and does warn: it means data was lost.
- **Every write goes through `writeKey`, and nothing it does can throw.** A write can be refused — every account on a device shares one origin's few megabytes, and a private window may refuse storage outright — and a refused `setItem` used to throw out of a React state update and take the whole screen down, **the emergency bar with it**. `writeKey` reports which record (never what was in it, nor whose), tells every `onWriteFailure` listener, and returns false; the board carries on from memory. `tests/app/structure.test.ts` holds `localStorage.setItem` to that one place, and checks what `writeKey`'s callers hand it the way it checks every other storage call.
- **A refused write puts up a strip that stays** — `.not-keeping`, at the top of the talk screen, in the flow rather than over it, with the dwells held as it arrives. A toast would be gone before a gaze reached it, and what it says is urgent: everything changed now is gone at the next reload. Its backup is built **from memory**, the one place the unsaved changes are. Amber, not red: red here means something is about to be destroyed, and this is somebody being told there is still time to keep it.
- **The phrase store is checked, every part of it, as it is read.** `loadPhraseStore` used to check that `custom` was a list and `overrides` an object and nothing about what was in them, so a phrase whose words were not words — an older release, a hand-edited file, another device — reached the parser while the board was drawn. It threw on every load, the damage staying put, so the crash screen's *Start again* would only have started the crash again; found by trying exactly that in a browser. Now each list and record keeps entries of the right shape and drops the rest: one damaged phrase costs that phrase, never the board.
- **A render that throws puts up the emergency bar, not a blank page.** `ErrorBoundary` in `talk/error-boundary.tsx` wraps every screen, inside the settings so the bar dwells at this person's speed. What it shows is read afresh from storage — the hooks that held the board may be what broke — through `core/board.ts`, so it is the bar this person arranged; where nothing would be left it is the six Peri ships, which need nothing to have survived. The report names the kind of error and nothing it said, a message being able to carry a phrase.
- **Tests capture Peri's own warnings and pass everything else through.** `warnings` in `tests/setup.ts` collects anything beginning `[Peri]` — nearly a thousand tests drive these paths deliberately — while React's warnings still reach the terminal, which is the whole point of having them.
